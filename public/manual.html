Overview

The service reads the live question, panelist queue, Next Up question and counters straight from Mukana's Firebase database and writes them to text layers and sources in mimoLive. It replaces the old Chrome extension: no browser has to stay open, and nothing depends on Mukana's page layout.

Mukana (Firebase)  ──streaming──▶  Sync service  ──HTTP──▶  mimoLive :8989
                                       ▲
                               this web UI :8790

When the host clicks Answer in Mukana panelView, mimoLive updates within a fraction of a second. When the question is done or cancelled, the mapped layers are cleared.

Install

# Node.js on macOS (or install the LTS package from nodejs.org)
brew install node

# Get the code
git clone https://github.com/Media-Event-AS/mukana-mimolive-sync.git
cd mukana-mimolive-sync

# Optional: run the tests
npm test

There is no npm install step. To update later: git pull in the repo folder, then restart the service.

Run

cd mukana-mimolive-sync
npm start

Open http://localhost:8790, or http://<machine-ip>:8790 from another machine on the LAN. Stop with Ctrl+C. If sync was running when the service stopped, it starts again automatically on the next launch.

Configure mimoLive

The service talks to mimoLive's built-in HTTP API. It is off until remote control is allowed. Do this once on the mimoLive machine:

  1. Open mimoLive, then choose mimoLive → Settings… from the menu bar (Preferences… in older versions).
  2. Open the Remote Control tab.
  3. Turn on Allow Remote Control Access.
  4. Password (optional): if you set a password in that tab, enter the same password in the mimoLive section of this UI. If you don't need one, leave it empty in both places.
  5. Keep the show document open in mimoLive. The API only lists open documents.

When the service runs on another machine

  • The API listens on port 8989. If the macOS firewall is on for the mimoLive Mac, allow incoming connections for mimoLive: System Settings → Network → Firewall → Options.
  • Quick test from the service machine: open http://<mimolive-ip>:8989/api/v1/documents in a browser. You should get JSON listing the open documents. A login prompt or HTTP 401 means a password is set.
Some mimoLive versions have a reported bug where a one-character password appears on its own after a restart. If Scan network shows 🔒 password required or the log says mimoLive requires a password, open the Remote Control tab and either clear the password or enter it here.

Do not expose port 8989 to the internet. mimoLive recommends a tunnel (such as ngrok) if you ever need remote access from outside the LAN.

First-time setup

  1. 1 · Mukana: enter the Event ID (the part after ?event= in the panelView URL, e.g. ohtest) and paste the refresh token (see below). Click Save.
  2. 2 · mimoLive: click Scan network and pick your mimoLive machine, or type its IP. Enter the password if mimoLive uses one. Click Load documents, choose the show document, then Save.
  3. 3 · Mapping: add one row per graphic element (see Mapping). Click Save mapping.
  4. Click Start sync in the header. The status should read LIVE · waiting, or LIVE · question on air when a question is being answered.

Settings are saved on this machine and survive restarts.

Getting the Mukana token

The service signs in to Mukana as you, using a long-lived refresh token from a normal browser session. You only do this once. The token renews itself every hour.

  1. Open Mukana panelView in Chrome or Safari and sign in with Google as host.
  2. Open the developer console: Chrome ⌥⌘J, Safari ⌥⌘C (enable Show features for web developers in Safari settings first).
  3. Run: 
    copy(firebase.auth().currentUser.refreshToken)
    The console prints undefined. That's expected: the token is now on your clipboard.
  4. Paste it into Refresh token and click Save. The field then shows Saved ✓.
The token is stored only in data/config.json on this machine and is never shown in the UI. Treat it like a password.
Google blocks sign-in inside embedded browsers (such as an app's built-in browser pane). Use a regular browser to get the token.

Mapping

Each row sends one Mukana field to one input of one mimoLive layer or source.

ColumnWhat to choose
Mukana fieldThe data, e.g. Name, Question (URL removed), Next up: name, Voting Qs (count).
mimoLive layer / sourceLoaded from the selected document. Layers and sources are listed by name.
Input keyThe input on that layer. Text layers normally use tvGroup_Content__Text_TypeMultiline, QR sources tvGroup_Content__QR_Content, note layers tvGroup_Note__Note_TypeMultiline.

One field can feed several layers (add more rows). If you add layers in mimoLive, click Reload layers. A green dot ● in the Live panel marks fields that are mapped.

ControlUse

Verify against mimoLiveReads every mapped input back from mimoLive and shows ✅ or ❌. Use it during rehearsal.

How it connects

Nothing is polled. The service opens a streaming connection to Firebase and Firebase pushes changes as they happen.

LinkMechanismTraffic
Mukana → service6 Firebase streams (Server-Sent Events): live question, hands, panelists online, On Deck, Voting Qs, Answered. One snapshot on connect, then only changes.Keep-alive about every 30 s. Silence when nothing changes.
AuthToken renewal with Google once per hour. Streams reconnect and re-download their snapshot.A few hundred KB per hour at most.
Service → mimoLiveHTTP to the mimoLive API, only when a mapped value changes.LAN only.
This UI → serviceStatus refresh every second while the page is open.LAN only.
Firebase bills for downloaded data and concurrent connections, and the Firebase project belongs to Mukana, not to us. The load is about the same as one extra panelist with panelView open, and lower in practice, since panelView also streams chat, likes and DMs.

Run in the background (macOS)

The easiest way is section 5 · Service in the control panel:

ButtonWhat it does
Start at loginInstalls a launchd agent. From the next login the service starts by itself, and it restarts if it stops. The current port, time zone and UI password are kept.
Start at login + move to background nowSame, and hands over right away: the terminal process stops and launchd runs the service. The page reconnects after a few seconds and you can close the terminal window.
Turn off start at loginRemoves the agent. If the service runs in the background, it also stops; start it again with npm start.

Buttons that stop the service ask you to click twice. The log is in ~/Library/Logs/mukana-mimolive-sync.log.

If you move the project folder or update Node.js (for example brew upgrade node), click Turn off start at login and then Start at login again so the agent gets the new paths.

Manual alternative

You can also install the launchd file in launchd/ yourself. Replace /path/to/mukana-mimolive-sync with your folder and check the node path (which node), then:

cp launchd/no.mediaevent.mukana-sync.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/no.mediaevent.mukana-sync.plist

# stop and remove
launchctl unload ~/Library/LaunchAgents/no.mediaevent.mukana-sync.plist

Log file for the manual alternative: /tmp/mukana-sync.log.

Linux / Windows: run npm start under systemd, pm2 or NSSM. There is no one-click option for those systems.

Troubleshooting

SymptomCause / fix
Token refresh failed: INVALID_REFRESH_TOKEN or TOKEN_EXPIREDThe token was revoked (signed out of Google everywhere, password change). Get a new token.
Stream error HTTP 401 Permission deniedWrong Event ID, or your account isn't host on this event.
Status stays LIVE · waiting while a question is on airCheck the Event ID matches the panelView URL (?event=…).
Scan network finds nothing / No connectionTurn on Allow Remote Control Access in mimoLive (Settings → Remote Control), check the firewall on the mimoLive Mac, and check the port (8989). See Configure mimoLive.
mimoLive requires a password / 🔒Authentication is on in mimoLive. Enter the same password in the mimoLive section, or clear it in mimoLive.
Values in the Live table but not in mimoLiveRun Verify against mimoLive. A ❌ with input key does not exist means the wrong input key is chosen for that layer.
mimoLive document reopened, layers emptyClick Resend all. Layer IDs survive reopening, so the mapping stays valid.
EADDRINUSE on startThe service is already running, or something else uses port 8790. Stop it or use PORT=….
URL in the question is cut offMukana limits questions to about 250 characters, so the URL is already truncated in Mukana.

Limitations

  • Mukana's data structure is undocumented (mapped from panelView v260113a). If Mukana changes it, the service may need an update.
  • Firebase settings (API key, database URL, origin) can be changed under Advanced for another Mukana instance.
  • One event per service instance. Run a second instance on another PORT with its own DATA_DIR for parallel events.
