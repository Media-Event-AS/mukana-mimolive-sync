Overview

The service reads the live question, panelist queue, Next Up question and counters straight from Mukana's Firebase database and writes them to text layers and sources in mimoLive. It replaces the old Chrome extension: no browser has to stay open, and nothing depends on Mukana's page layout.

Mukana (Firebase)  ──streaming──▶  Sync service  ──HTTP──▶  mimoLive :8989
                                       ▲
                               this web UI :8790

When the host clicks Answer in Mukana panelView, mimoLive updates within a fraction of a second. When the question is done or cancelled, the mapped layers are cleared.

Install

macOS: one command (recommended)

Works on a fresh Mac. You do not need Homebrew, Node.js or Git first.

  1. Open Terminal (press ⌘ Space, type Terminal, press Return).
  2. Paste this line and press Return: 
    curl -fsSL https://raw.githubusercontent.com/Media-Event-AS/mukana-mimolive-sync/main/install-mac.sh | bash
  3. If Node.js is missing, the installer downloads the official LTS version from nodejs.org and asks for your Mac login password. Nothing shows while you type. Press Return when done.
  4. Wait for Done!. Every step should show a green ✔. Answer Y to start the service now.

The app is installed in ~/mukana-mimolive-sync (your home folder). The installer also makes sure node and npm work in new Terminal windows and checks that they do.

Update: run the same command again. Your settings in data/ are kept.

If you see a red ✘, copy the whole Terminal window and send it to ronny@mediaevent.no.

Manual install (any OS)

# 1. Node.js 18.17 or newer: install the LTS package from https://nodejs.org
node -v

# 2. Get the code
git clone https://github.com/Media-Event-AS/mukana-mimolive-sync.git
cd mukana-mimolive-sync

# Optional: run the tests
npm test

There is no npm install step. To update later: git pull in the repo folder, then restart the service.

Run

On a Mac, double-click start-mac.command in the mukana-mimolive-sync folder. A Terminal window opens and runs the service, and the web UI opens in your browser. Or, in Terminal:

cd ~/mukana-mimolive-sync
npm start

Open http://localhost:8790, or http://<machine-ip>:8790 from another machine on the LAN. Stop with Ctrl+C. If sync was running when the service stopped, it starts again automatically on the next launch.

Configure mimoLive

The service talks to mimoLive's built-in HTTP API. It is off until remote control is allowed. Do this once on the mimoLive machine:

  1. Open mimoLive, then choose mimoLive → Settings… from the menu bar (Preferences… in older versions).
  2. Open the Remote Control tab.
  3. Turn on Allow Remote Control Access.
  4. Password (optional): if you set a password in that tab, enter the same password in the mimoLive section of this UI. If you don't need one, leave it empty in both places.
  5. Keep the show document open in mimoLive. The API only lists open documents.

When the service runs on another machine

  • The API listens on port 8989. If the macOS firewall is on for the mimoLive Mac, allow incoming connections for mimoLive: System Settings → Network → Firewall → Options.
  • Quick test from the service machine: open http://<mimolive-ip>:8989/api/v1/documents in a browser. You should get JSON listing the open documents. A login prompt or HTTP 401 means a password is set.
Some mimoLive versions have a reported bug where a one-character password appears on its own after a restart. If Scan network shows 🔒 password required or the log says mimoLive requires a password, open the Remote Control tab and either clear the password or enter it here.

Do not expose port 8989 to the internet. mimoLive recommends a tunnel (such as ngrok) if you ever need remote access from outside the LAN.

Show profiles

The Show profile bar at the top switches between shows. A profile holds the Event ID and Mukana login token (🔑), the mimoLive machine and document, the mapping, the cue list and the panelists (people, layouts, lower third, pre-flight list). The mimoLive password and the Service settings stay on this machine.

ButtonDoes
LoadSwitches to the selected show (click twice). The profile's token is used, so you don't need a new one. A profile without a token keeps the current login. Mukana reconnects if the event or login changed.
Save / Save as…Saves the current show over its profile, or under a new name. The bar shows saved or unsaved changes.
New showEmpties Event ID, document, mapping, cue list and panelists (click twice). The login token and the mimoLive machine are kept.
Download / UploadA profile as a file, e.g. to move a show to another machine. The download leaves out the login token unless you tick incl. login token. Only tick it for your own machines: anyone with the file can sign in to Mukana as you.
DeleteRemoves the selected profile from this machine (click twice).
After Load and New show, Auto layers is off, so a show never fires cues before you are ready. Turn it on in the Live section.

First-time setup

  1. 1 · Mukana: enter the Event ID (the part after ?event= in the panelView URL, e.g. ohtest) and paste the refresh token (see below). Click Save.
  2. 2 · mimoLive: click Scan network and pick your mimoLive machine, or type its IP. Enter the password if mimoLive uses one. Click Load documents, choose the show document, then Save.
  3. 3 · Mapping: add one row per graphic element (see Mapping). Click Save mapping.
  4. 4 · Layer control (optional): a cue list that takes layers and layer sets live and off (see Layer control).
  5. 5 · Panelists (optional): sources, layouts and lower thirds for panelists (see Panelists).
  6. Click Start sync in the header. The status should read LIVE · waiting, or LIVE · question on air when a question is being answered.

Settings are saved on this machine and survive restarts.

Getting the Mukana token

The service signs in to Mukana as you, using a long-lived refresh token from a normal browser session. You only do this once. The token renews itself every hour.

  1. Open Mukana panelView in Chrome or Safari and sign in with Google as host.
  2. Open the developer console: Chrome ⌥⌘J, Safari ⌥⌘C (enable Show features for web developers in Safari settings first).
  3. Run: 
    copy(firebase.auth().currentUser.refreshToken)
    The console prints undefined. That's expected: the token is now on your clipboard.
  4. Paste it into Refresh token and click Save. The field then shows Saved ✓.
The token is stored only in data/config.json on this machine and is never shown in the UI. Treat it like a password.
Google blocks sign-in inside embedded browsers (such as an app's built-in browser pane). Use a regular browser to get the token.

Layer control (cue list)

Section 4 · Layer control is a cue list that works like QLab. Each row is a cue:

ColumnMeaning
TriggerWhat fires the cue: a Mukana event (only while Auto layers is on), GO / Companion, or — (only reached from the cue above). Every cue can also be fired with its GO button (save first).
Pre-waitSeconds between firing and doing the action. The Now column counts down.
ActionRecall layer set · Layers live / Layers off (one or more layers, ⌘/Ctrl-click; off is done when they are fully off) · Switch off a set's layers · Panelist layout · Panelist lower third · Source into slot · Role into slot (see Panelists) · Write text into a layer or source input ({name}, {location} and other field names are replaced by the live question) · Trigger signal · Wait N seconds, or pause until GO / Continue or a Mukana event (the seconds are then an optional timeout; empty = no timeout) · Fire cue
Continue— stops here. Auto-continue starts the next cue at the same moment as this one, so the pre-waits of a run of auto-continued cues read like a timeline (0 s, 3 s, 6 s…). Auto-follow starts the next cue when this one is done.
CancelsCue numbers to stop when this cue fires, e.g. 2, 3.

A paused cue shows ⏸ paused and its GO button becomes Continue: GO on a paused cue continues it instead of restarting it. A cue paused until a Mukana event continues by itself when that happens. A cue fired again while it runs restarts and stops what it started. Stop all cues stops everything at once (no confirm: it is the panic button). Turning Auto layers off also stops running cues; GO still works. Use ↑ ↓ to reorder; Cancels and Fire cue keep pointing at the same cues. Click Save cues when done.

Mukana events: question goes live · next question replaces the live one (also counts as goes live) · question done or cancelled · host marks done reading · panelist raises hand (below the line) · panelist moved above the line · panelist starts answering · panelists answering change (join, leave, switch) · last panelist stops answering (also when the question ends while panelists answer) · host notes added or changed. Hand and notes events only count within the same question. The host never counts as answering.

Question text timing is built in. When the question changes, text in layers a cue has taken live is held at what is on screen. A cue that takes such a layer live first takes it off, then writes the new text. A cue that takes it off clears the text once it is off.

Example:

#NameTriggerPre-waitActionContinueCancels
1Question onQuestion goes live0Recall “2UP w/question”Auto-follow
2Back to host—12Recall “Fullscreen 1”—
3Question doneQuestion done or cancelled0Recall “Fullscreen 1”—1, 2

Simulate

The Simulate Mukana buttons act as if the event happened in Mukana: cues fire and question text and panelists follow. mimoLive is driven for real. The first click switches from Mukana to a sample question (the header shows SIMULATING); Mukana is ignored until you click End simulation. Pick a person from the People table for hand events, or use the sample panelist.

Companion / Stream Deck

Companion (or any HTTP tool) can fire, continue and stop cues: POST /api/cues/<number>/go, …/continue, …/stop, POST /api/cues/stop-all, POST /api/auto-layers (toggle), POST /api/simulate/<event>. GET /api/cues returns the state for button colours: Auto layers, question live, who is answering, and per cue whether it is running. See the README for the full list.

Panelists

5 · Panelists holds who is who, their video sources and lower thirds, and which layout to use for how many are answering. Nothing in it runs by itself: the cue list decides when, with these actions:

Cue actionWhat it does
Panel layout (above the line)The panel for this question: everyone the host approved above the line (and anyone answering), in queue order. Picks the layout for that many, puts their sources into the slots (B, C…; the host stays in A) and recalls the layout's set. For when the host presents the panel before going to each of them. Hands below the line are not shown.
Answering layout (who answers now)The same, but only who is answering right now, in a shot: With host, Answering only or Current shot (the last one chosen; back to with host on each new question). When one leaves, the others shift up. Nobody answering: nothing changes. Going from the panel shot to this one always counts as a new shot.
Panelist lower thirdWith exactly one panelist who just started: their name and title into the lower third, then live.
Change shotWith host, Answering only or Host only, right away. The first two become the current shot; host only is momentary: the next panelist comes back in the last shot. Put three GO cues for these on Stream Deck buttons.
Role into slotThe reader (or host) into a slot, e.g. the reader into B while the question is read.
Source into slotA fixed source into a slot.

Both layout actions place whoever qualifies when the cue runs; they don't wait. A typical flow: question goes live → host, reader and question → Panel layout → Wait until GO / Continue (or until Panelist starts answering) → the host clicks the first panelist in Mukana, which fires Answering layout → lower third → next panelist…

Roles: the host never counts and is never placed by the layout actions. The reader is placed by Role into slot while the question is read and counts as a panelist only while above the line or answering on that question. Panelists fill the slots when they answer.

Add panelist cues to the cue list adds a working set: Reader into B (question goes live, then your question cue), Question overlay off (first panelist starts answering), a per-panelist timeline (Answering · with host at 0 s → Panelist name at Show after → Go single at 6 s → Panelist name off at Show after + Off after, all auto-continue), Panelists done (last panelist stops: lower third off), and GO cues Shot: with host / answering only / host only. Every panelist the host clicks restarts the timeline for them.

In MukanaOn air (with those cues)
Nobody → 1 answeringQuestion overlay off; source into B, recall the 1-panelist layout; lower third after the delay.
A question goes live with a panelist already answeringOnly the question cues run. Panelist cues start when someone is made answering while the question is live.
Panelist 1 → panelist 2 (still one)Lower third out, B cuts to panelist 2, panelist 2's lower third after the delay. The layout stays.
A second panelist joinsSources into B and C, recall the 2-panelist layout. The lower third goes off: none with several.
A panelist leaves while others stayThe rest shift up (C → B) and the smaller layout is recalled. No new lower third.
Nobody answering any more, or the question endsThe layout stays; the lower third goes off.

Set it up in 5 · Panelists, then click Save panelists:

PartWhat to enter
Lower thirdThe lower third layer (a layer named “Lower Third” is suggested), Show after and Off after in seconds (empty = stays on), and How: Write name + title into it (default) writes the person's name and title into the layer's text inputs while it is off, then takes it live. One variant per person takes the person's own variant live instead. Name goes into / Title goes into pick the inputs; the defaults fit mimoLive's Lower Third layer.
PeopleOne row per person: Mukana person → role → video source → Name on screen (empty = their Mukana name) and Title. People added from Mukana get their Mukana location as the title to start with, so the lower third shows name + location; type over it for a job title. In variant mode: their variant instead. The role is Panelist, Host or Reader (see Roles above). You pick from everyone who raised a hand on the pre-flight question (its text contains “Pre-flight checklist”). Mukana drops the hands once that question is answered, so the service captures them while it is live or on deck. Sync must be running then. The list is kept after the question moves to Answered. Until anyone has raised a hand, you pick from the panelists online now (hosts excluded). Add all from pre-flight adds everyone on the list. For people who arrive after the pre-flight question is done, ask them to raise a hand on any live question and click Add all from current question: everyone with a hand up on the live question is added (and put on the list). Clear pre-flight list starts over. The variant is suggested when its name starts with the panelist's name. Panelists are matched by their Mukana ID, so a changed display name still matches. Video sources are grouped by type: Zoom, Camera inputs and NDI first.
LayoutsOne row per number of people and shot: the layer set to recall, the layer that holds the slots (suggested from the set's name) and the slots. With host: host in A, people from B. Answering only: people from A (e.g. 1 → “Fullscreen 2”, layer “Full Screen”, slot A). Host only: one row with how many = 0 and just the set to recall. With more people than the largest layout, the largest is used.
The source goes into the slot before the layout is recalled, so it comes up with the right people in it. The service only acts when something changes in Mukana, so the TD can change sources and layouts in mimoLive at any time. A panelist who is not in the table still counts for the layout, but gets no source and no lower third (see the log). Other automations that write into the same lower third, such as an automation layer that copies Zoom names into its variants, overwrite the name and title: remove them from your layer sets when you use this.

How it connects

Nothing is polled. The service opens a streaming connection to Firebase and Firebase pushes changes as they happen.

LinkMechanismTraffic
Mukana → service6 Firebase streams (Server-Sent Events): live question, hands, panelists online, On Deck, Voting Qs, Answered. One snapshot on connect, then only changes.Keep-alive about every 30 s. Silence when nothing changes.
AuthToken renewal with Google once per hour. Streams reconnect and re-download their snapshot.A few hundred KB per hour at most.
Service → mimoLiveHTTP to the mimoLive API, only when a mapped value changes.LAN only.
This UI → serviceStatus refresh every second while the page is open.LAN only.
Firebase bills for downloaded data and concurrent connections, and the Firebase project belongs to Mukana, not to us. The load is about the same as one extra panelist with panelView open, and lower in practice, since panelView also streams chat, likes and DMs.

Change address and port

In 7 · Service, choose where the web UI listens and on which port, then click Apply:

ChoiceWho can open the UI
0.0.0.0 — All interfacesEveryone on the LAN, and this machine (default)
127.0.0.1 — This machine onlyOnly a browser on the machine running the service
A specific IP (e.g. 192.168.1.20)Only via that network interface

The service opens the new address first and keeps the old one if that fails (for example if the port is in use), so you can't lock yourself out by mistake. The page then moves to the new address. If HOST or PORT is set as an environment variable, that field is locked in the UI.

Run in the background (macOS)

The easiest way is section 7 · Service in the control panel:

ButtonWhat it does
Start at loginInstalls a launchd agent. From the next login the service starts by itself, and it restarts if it stops. The current port, time zone and UI password are kept.
Start at login + move to background nowSame, and hands over right away: the terminal process stops and launchd runs the service. The page reconnects after a few seconds and you can close the terminal window.
Turn off start at loginRemoves the agent. If the service runs in the background, it also stops; start it again with npm start.

Buttons that stop the service ask you to click twice. The log is in ~/Library/Logs/mukana-mimolive-sync.log.

If you move the project folder or update Node.js (for example brew upgrade node), click Turn off start at login and then Start at login again so the agent gets the new paths.

Manual alternative

You can also install the launchd file in launchd/ yourself. Replace /path/to/mukana-mimolive-sync with your folder and check the node path (which node), then:

cp launchd/no.mediaevent.mukana-sync.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/no.mediaevent.mukana-sync.plist

# stop and remove
launchctl unload ~/Library/LaunchAgents/no.mediaevent.mukana-sync.plist

Log file for the manual alternative: /tmp/mukana-sync.log.

Linux / Windows: run npm start under systemd, pm2 or NSSM. There is no one-click option for those systems.

Troubleshooting

SymptomCause / fix
A panelist is missing from the Mukana panelist listThey have not raised a hand on the pre-flight question while sync was running. Ask them to raise it again (the question must be live or on deck), or pick them while they are online.
command not found: brewHomebrew is not needed. Use the one-command installer.
command not found: npm or nodeNode.js is missing or not on the PATH. Run the installer, then open a new Terminal window.
Missing script: "start"Wrong folder. Run cd ~/mukana-mimolive-sync first, or double-click start-mac.command.
Token refresh failed: INVALID_REFRESH_TOKEN or TOKEN_EXPIREDThe token was revoked (signed out of Google everywhere, password change). Get a new token.
Stream error HTTP 401 Permission deniedWrong Event ID, or your account isn't host on this event.
Status stays LIVE · waiting while a question is on airCheck the Event ID matches the panelView URL (?event=…).
Scan network finds nothing / No connectionTurn on Allow Remote Control Access in mimoLive (Settings → Remote Control), check the firewall on the mimoLive Mac, and check the port (8989). See Configure mimoLive.
mimoLive requires a password / 🔒Authentication is on in mimoLive. Enter the same password in the mimoLive section, or clear it in mimoLive.
Values in the Live table but not in mimoLiveRun Verify against mimoLive. A ❌ with input key does not exist means the wrong input key is chosen for that layer.
mimoLive document reopened, layers emptyClick Resend all. Layer IDs survive reopening, so the mapping stays valid.
EADDRINUSE on startThe service is already running, or something else uses port 8790. Stop it or use PORT=….
URL in the question is cut offMukana limits questions to about 250 characters, so the URL is already truncated in Mukana.

Limitations

  • Mukana's data structure is undocumented (mapped from panelView v260113a). If Mukana changes it, the service may need an update.
  • Firebase settings (API key, database URL, origin) can be changed under Advanced for another Mukana instance.
  • One event per service instance. Run a second instance on another PORT with its own DATA_DIR for parallel events.
